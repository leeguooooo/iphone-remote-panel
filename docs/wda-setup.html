Direct/WDA 主路径 — 接入、边界与真机验收

iphone-use 默认用 WebDriverAgent 直接连接 iPhone：控制走 127.0.0.1:8100，手机端 MJPEG 画面走 127.0.0.1:9100。 浏览器看 /agent/mjpeg、控 /control，agent 走 /agent/*。 默认不打开 iPhone 镜像，也不申请 Mac 的录屏或辅助功能权限。

为什么把它设成主路径

WebDriverAgent（WDA，Appium 的 iOS 底座）作为 XCUITest runner 跑在手机上： 能读 iOS 元素树、直接送 Unicode 文本，并由手机合成点按和手势。画面来自同一个 WDA 会话的 MJPEG 服务，不再依赖 Mac 上的镜像窗口、前台焦点或真实光标。WDA 不可达时，direct 模式会明确失败， 不会悄悄回退去操作 Mac。

能力Direct/WDA 默认Legacy mirror
画面WDA MJPEG → /agent/mjpeg；失败时可降级 PNG 静帧iPhone 镜像 → ScreenCaptureKit → WebRTC
浏览器控制POST /control，每条命令有成功/失败响应WebRTC data channel → CGEvent
Agent 控制/agent/input、/agent/elements、/agent/screenshotMac 侧像素/键码兜底
Mac 权限不需要 iPhone 镜像、录屏、辅助功能三者都需要
前置成本完整 Xcode、开发团队签名、开发者模式、配对/信任iPhone 镜像可用且保持可连接

首次接入（安装 daemon，再接真机）

curl -fsSL https://raw.githubusercontent.com/leeguooooo/iphone-use/main/install.sh | sh

# 保持手机 USB 连接、已信任、已解锁且亮屏
~/.iphone-use/setup-wda.sh doctor
~/.iphone-use/setup-wda.sh
~/.iphone-use/setup-wda.sh status

install.sh 负责 daemon、LaunchAgent 和默认 direct 配置；它不等于真机已跑通。 setup-wda.sh 才负责 WDA 编译/签名/装机、runner、8100 控制中继和 9100 MJPEG 中继。 浏览器打开 /setup 可看到产品内的四步连接向导和实时首要阻塞项；只有 backend:"direct" 且 drivable:true 时才开放进入控制页。 向导只读状态，不会替操作者修改 VPN/代理、选择设备、绕过系统信任或执行设置脚本。 doctor 会检查 Xcode、开发团队、WARP/VPN、macOS 系统代理、设备、信任和中继工具。 它只报告网络阻塞，不会自动断开 WARP/VPN，也不会修改 HTTP/HTTPS/SOCKS 代理。 进度写入 ~/.iphone-use/wda-setup-status.json，daemon 通过 /agent/status 的 setup_blocked_on 暴露 warp|proxy|usb|trust|ddi|wda 等首要阻塞点。KeepAlive 下一次重试开始时 保留上一次 blocker，直到对应检查确实通过或被新的原因替换，避免状态在真实故障与空值之间闪烁。

前置条件

  • Mac：安装完整 Xcode.app，仅 Command Line Tools 不够；在 Xcode → Settings → Accounts 登录 Apple ID 并选定 Apple 开发团队（免费 Personal Team 可用，但签名通常需周期性续装）。
  • iPhone：开启开发者模式（设置 → 隐私与安全性 → 开发者模式 → 开 → 重启）。
  • 连接：首次优先 USB；Mac 与 iPhone 已配对，手机上点过信任。
  • 运行：编译、启动和控制期间保持手机解锁、亮屏、唤醒；WDA 不能绕过 Face ID/密码。
  • 中继工具：普通路径使用 USB iproxy，安装命令为 brew install libimobiledevice。脚本不会在 USB 不可用时自动切到 Wi-Fi/ socat；后者只属于操作者明确配置的手动实验。
  • 多设备 Mac：daemon 固定 PHONE_REMOTE_UDID，运行 setup 时把同一个 classic UDID 传为 WDA_UDID，避免恢复时换错手机。

Direct API：同一条手机端链路

direct 安装默认配置 PHONE_REMOTE_WDA_URL=http://127.0.0.1:8100 和 PHONE_REMOTE_WDA_MJPEG_URL=http://127.0.0.1:9100。 两者都由 setup 脚本建立本地中继；控制失败不会回退到镜像/CGEvent。

调用路由说明
GET /agent/mjpeg9100 → daemon → 浏览器手机端实时画面；中继失败时 UI 应明确降级或离线
POST /control浏览器 → 8100 WDAcookie 鉴权 + X-Phone-Control: 1；每条命令返回确认
POST /agent/input {"type":"text","text":"你好"}8100 WDA中文直通（Unicode 进入文本框，不被 Mac 键码/IME 吃）
POST /agent/input {"type":"tap","label":"新备忘录"}8100 WDA精确标签唯一时才点；零匹配或重名返回 422 且不发送动作
POST /agent/input {"type":"tap","x":0.5,"y":0.5}8100 WDA归一化坐标，由手机合成
Home / Spotlight / named key8100 WDA设备端按钮、主屏幕 Search 入口和 WebDriver key；不触发 Mac 键码
long-press / swipe / drag8100 WDA Actions完整手势一次提交并等待 HTTP 确认，不依赖 WebRTC move channel
GET /agent/elements8100 WDA带 snapshot 的扁平元素树；包含 label、identifier、kind、rect 和稀疏状态字段
GET /agent/screenshot8100 WDA手机端 PNG 截图；无需镜像窗口
App Switcher / Control Center / Shortcuts bridgeDirect 暂不支持旧实现依赖镜像、Mac 光标/剪贴板；必须有设备端实现并真机验收后再宣称支持

自动化应以 GET /agent/status 的 backend:"direct"、wda:true、 wda_actionable:true、drivable:true 为门槛。 device_state 还会暴露 releasing 和 reconnecting，调用方应等待它回到 ready。 phone_target / mirror_state 属于 legacy mirror 语义，不能证明 direct 可控。

踩坑清单(真机验证)

① 让 DDI 挂载:手机必须解锁 + 保持连接 真·头号坑

开发服务起不来时报 "Developer Disk Image is not mounted… Ensure that the device is unlocked",devicectl 显示 ddiServicesAvailable: false。**最常见的真实原因是手机锁屏 / 刚连上还没握手完**,不是版本问题。修复:**解锁手机、保持亮屏不锁、保持连接(USB 最稳)**,等 ddiServicesAvailable 翻成 true 再 build。可以轮询等:

until xcrun devicectl device info details --device <UUID> \
  | grep -q "ddiServicesAvailable: true"; do sleep 4; done
更正一个曾经的误判: 一度以为「设备 iOS 大版本必须 ≤ Xcode 的 DDI」是硬性卡点(iOS 27 设备 + Xcode 26.5)。真机验证推翻了它 —— Xcode 26.5(DDI build 17F42 = iOS 26.5)成功把 WDA 装上了 iOS 27.0 的设备并尝试启动。所以「版本差一截」往往能用,真正卡住的是解锁/连接(本坑)和证书信任(见「手机上要信任开发者证书」一节)。只有当 DDI 比设备老很多、确实拒绝挂载时才需要升 Xcode。

② 手机上要信任开发者证书 必撞

编译/签名/装机都成功后,启动 runner 报 "The application could not be launched because the Developer App Certificate is not trusted."(或更隐晦的 "Lost pending connection to the test runner before launch")。这不是构建失败,是 iOS 拒绝启动未受信任的开发者 app。

修复:手机上 设置 → 通用 → VPN 与设备管理 → 「开发者 App」下选你的 Apple Development 证书 → 信任。注意找的是「Apple Development: <Apple ID>」证书,不是 app 名(app 显示为 WebDriverAgentRunner)。 换 bundle id 重装后要重新信任一次。

③ 两套设备 ID,别搞混

xcrun devicectl list devices 显示的是 CoreDevice UUID(如 96ECE27A-…);xcodebuild -destination "id=…" 要的是老式 UDID(如 00008150-000A…)。用错直接报 "Unable to find a device matching the provided destination specifier"。查正确 UDID:xcodebuild -showdestinations 或 devicectl device info details 里的 udid 字段。

④ 未登录开发团队 → 签名失败

新机器 security find-identity -p codesigning 返回 0,xcodebuild 报 "Signing for WebDriverAgentRunner requires a development team"。修复:Xcode → Settings → Accounts 登录 Apple ID;证书首次编译用 -allowProvisioningUpdates 自动生成。

⑤ 不能用 PRODUCT_NAME 改显示名(会搞坏构建)

想把手机上的 app 名从 WebDriverAgentRunner 换成自己的品牌,千万别在命令行传 PRODUCT_NAME=… —— 它是全局覆盖,会把 WDA 的内部框架 WebDriverAgentLib 也改名,导致它自身的 #import <WebDriverAgentLib/FBElement.h> 全部找不到、编译失败。安全的只有 PRODUCT_BUNDLE_IDENTIFIER(全局覆盖无害)。干净改显示名要改单个 target 的设置(放进 setup 脚本),不能粗暴全局覆盖。

⑥ 免费账号签名 7 天过期

免费 Personal Team 签出来的 WDA 7 天失效,要每周重装;付费开发者账号(¥688/年)签名一年有效。长期部署建议付费账号。

⑦ macOS「本地网络」隐私会静默拦截 daemon 直连手机 必须走 localhost 中继

真机实测:终端里 curl http://<phone-ip>:8100/status 通,但 daemon(后台 LaunchAgent)发同样的请求失败、不弹任何授权框 —— macOS 15+/26 的「本地网络」隐私对后台进程访问私网地址是静默拒绝。

普通路径让 daemon 只访问 127.0.0.1，由 USB iproxy 把 8100/9100 固定转发到 WDA_UDID。这样能稳定选择目标， 也不依赖变化的手机 IP。脚本不会自动改用 Wi-Fi/socat；需要那条路径时， 操作者必须自己评估网络和暴露面后手动配置。

loopback 不是认证或防火墙。 WDA 在 iPhone 上的 8100/9100 没有认证。iproxy 只保护 Mac 侧 relay 的目标选择，不能阻止同一局域网里的机器 直接访问手机 IP 上的 WDA。Phase 1 只适合可信、隔离网络；真正的设备传输认证要由 Phase 2 companion app 或受控 tunnel 提供。

⑧ WDA 端口会暴露到可路由网络；锁屏也会阻断操作

WDA 监听手机的 0.0.0.0:8100，MJPEG 使用 9100，二者都无认证。 日志打印 ServerURLHere->http://<phone-ip>:8100<-ServerURLHere。 只要网络可路由，同 LAN/跨子网主机可能绕过 daemon 登录直接访问 WDA。不要在访客 Wi-Fi、 公共网络或不受控办公网运行 Phase 1；用 USB 时可关闭手机 Wi-Fi。

很多操作（启动 App、输入）要求手机解锁。默认自动锁定会反复打断，长时间测试可在 设置 → 显示与亮度 → 自动锁定 调整；首次解锁仍需真人，WDA 不能绕过 Face ID/密码。

⑨ WDA 与 iPhone 镜像互斥：不要把两条链路叠加 架构级

跑在手机上的 XCUITest runner(WDA)会独占设备的远程会话:它一启动,iPhone 镜像立刻断成 「Connection Interrupted」;它活着,镜像点 Try Again 永远连不回去 —— 哪怕手机已锁屏。 反向同样成立,先连镜像再启 runner,镜像当场被踢掉。真机 A/B 实测(iPhone 17 / iOS 27,2026-06-12): 带着 WDA 点 Try Again → 失败;杀掉 runner 再点 → 秒连;镜像连着时重启 runner → 镜像当场断。

所以 direct 与 legacy mirror 是两个明确后端，不是运行时自动兜底：

  • Direct（默认）：WDA 控制 + WDA MJPEG 画面。不要打开 iPhone 镜像；镜像显示 Interrupted 属正常。
  • Legacy mirror（显式兼容）：先停 WDA，再以 PHONE_REMOTE_BACKEND=mirror 重启 daemon，并在镜像窗口重新连接。此模式才申请录屏/辅助功能。

direct 后端不会接受「切到 mirror」作为一次普通控制命令；这是部署级选择，必须明确改配置并重启。 排障时先确认自己选择的是哪一个 backend，再查 curl http://127.0.0.1:8100/status 和两个 relay，避免一边启动 WDA、一边反复点镜像重连。

⑩ WARP / 任何 VPN 会卡死 CoreDevice 设备隧道 → WDA 根本装不上 #1 头号坑(真因)

这是花了整整一晚才揪出来的真凶。症状极具迷惑性:xcodebuild 永远 Device is busy (Connecting to iPhone)、devicectl device info details 永久挂起、 设备隧道死在 connecting 不肯到 available。试遍重插 USB、kickstart usbd/usbmuxd/remoted、 重启手机、甚至重启 Mac 全都没用。

真因 = Cloudflare WARP(或任何 VPN):iOS 17+ 的 CoreDevice 靠一条网络隧道(RSD/utun)连真机 ——哪怕走 USB 也要建虚拟网络接口,WARP 劫持路由把它卡死。实锤:warp-cli disconnect 后 24 秒设备就从 connecting → available,xcodebuild 立刻能装。而且 xcodebuild test 的 XCUITest 会话全程要靠 CoreDevice 维持 runner 存活,所以 WARP 一旦重连,runner 当场死 (Testing failed: The connection was invalidated)。

解法:

  • 临时:由操作者决定是否执行 warp-cli disconnect。 setup-wda.sh doctor 只检测并说明问题，脚本不会自动断开或恢复 WARP/VPN。 若组织策略是 Always On: true，交给管理员处理，不要让安装脚本绕过策略。
  • 永久（只访问少量目标时优先）:让 Zero Trust 管理员创建匹配该用户或设备组的配置， 将 Service mode 设为 Traffic only、Split Tunnels 设为 Include， 并只加入真正需要 WARP 的目标 IP/CIDR。系统 DNS 和其他目的流量不进 WARP，CoreDevice 也不会被捕获。 Traffic only 不支持按域名动态分流，因此先确认目标的稳定 IP。
  • 短 HTTP 请求的备选:MASQUE + Local proxy mode 只转发显式发给 127.0.0.1:40000 的 HTTP/HTTPS 请求，同样不会捕获 CoreDevice；但 Cloudflare 对这种模式设有 单次请求超时，不适合可能持续较久的 Git 上传。
  • 永久（仍需全隧道时）:让 Zero Trust 管理员在 WARP 设备配置的 Split Tunnels 排除列表里 加上 CoreDevice 设备隧道的 IPv6 段（fe80::/10 链路本地 + fd00::/8 设备 RSD ULA）。以 warp-cli tunnel dump 的 Excluded 有效路由为准，不要只看较短的策略摘要。 这样 CoreDevice 不走 WARP,WDA 就能在 WARP 开着时跑——真正做到「办公 VPN + 操作手机」两不误。

排障速记：WDA / 真机装不上时先看 setup-wda.sh doctor、warp-cli settings 和 warp-cli status。脚本会验证 Traffic only / Include 的有效排除路由，并将 Local proxy mode 视为路由安全；是否切换 VPN 状态或组织策略由操作者或管理员决定。

已有真机证据（组件级）

在 iPhone 17 / iOS 27 真机（2026-06-11）上，以下 WDA 组件能力曾经通过 daemon API 实测：

  • GET /source — 元素树直接读到中文 UI(设置项、日期标签)。
  • 按元素 label 定位 + 点击 — 无坐标漂移、不碰 Mac 光标(用它驱动设置把自动锁定设成「永不」,人没动电脑)。
  • POST /wda/keys 送字符串 — 中文一次到位:在备忘录里干净打出整段中文,而同机 L3 像素路径打出的是 我爱上…AI阿根廷鸥鸟啊 这种被拼音 IME 吃 keycode 的乱码。WDA 直接把 Unicode 送进文本框,绕开键盘/IME。

这些证据证明 WDA 组件可行，不等于当前 direct-by-default 的安装器、MJPEG、 浏览器手势、故障恢复和多设备选择已经完整验收。
