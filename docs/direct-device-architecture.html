Direct Device 架构与真机验收

当前默认链路是 WebDriverAgent 输入与 WDA MJPEG 画面。浏览器通过守护进程控制手机， 不读取 Mac 屏幕，也不向 Mac 注入事件。本文记录现有实现、迁移步骤和可执行验收条件。

决策边界

Direct 失败时不得退回 Mirroring。 WDA 不可用、请求无效或设备已释放时，服务返回失败；Mac 侧的 ScreenCaptureKit、 CGEvent 和 iPhone Mirroring 路径保持关闭。
问题 当前决定 验收证据
默认后端 direct。服务端遇到未设置或未知值也选 direct；安装器遇到未知值会直接报错。 /agent/status.backend == "direct"，启动日志写出 backend: direct。
画面与输入 Phase 1 使用 WDA 的 MJPEG 与 WDA actions。画面与控制共享同一台手机，但经不同的 loopback relay。 127.0.0.1:8100/status 可用；/agent/mjpeg 持续返回 multipart 帧；控制请求收到 ACK。
旧路径 只有显式设置 PHONE_REMOTE_BACKEND=mirror 才启用 legacy Mirroring。 Direct 模式不启动 TCC preflight、AppKit、ScreenCaptureKit pipeline 或 CGEvent injector。
Phase 2 仅评估 iOS ScreenCaptureKit companion app。当前仓库没有 companion target，也没有 entitlement 可用性证据。 Xcode、iOS 27 真机和 entitlement 三道闸门全部通过后，才允许进入实现评审。
“已实现”不等于“已在每台目标机验收”。 Phase 1 已有代码和安装链路；发布结论仍要附上本文矩阵中的真机证据。源码检查、单元测试和 “进程在跑”都不能替代画面、输入、锁屏恢复与卸载检查。

当前架构

画面

默认画面来自 WDA MJPEG。setup-wda.sh 把设备端 :9100 转发到 127.0.0.1:9100，daemon 再通过 /agent/mjpeg 代理给浏览器。

MJPEG relay 是 best-effort。它失效时，浏览器每 2.5 秒请求一次 WDA PNG 截图； 控制链路可以继续工作。降级画面不能冒充实时画面。

控制

Direct 浏览器不建立 /ws、RTCPeerConnection 或 WebRTC data channel。 每个完整手势在 pointer-up 后变成一次 HTTP 请求。

tap、longpress、swipe、drag、text、key、keyboard、Home、Back 和 Spotlight 走 WDA。Mirroring 时代的连续 down/move/up 协议在 direct 中不接受。

维度 Direct（默认） Mirror（兼容模式）
选择方式 未设置、direct 或服务端未知值 仅支持显式 PHONE_REMOTE_BACKEND=mirror
画面 WDA MJPEG；失败后 WDA PNG 降级 ScreenCaptureKit → VideoToolbox H.264 → WebRTC
输入 POST /control → WDA action WebRTC data channel → CGEvent
Mac 权限 不需要 Screen Recording / Accessibility 两项 TCC 都需要
失败行为 返回 4xx/503；不碰 Mac 只在用户明确选择后维持旧逻辑
App Switcher 不支持 保留旧 L3 shortcut

浏览器控制契约

浏览器发出的 direct 控制必须满足四个条件：同源登录 cookie 有效、请求头 X-Phone-Control: 1 存在、backend 是 direct、WDA 成功执行动作。 客户端只有在 HTTP 成功且 JSON 为 {"ok":true} 时才能展示成功反馈。

HTTP 响应 含义与客户端行为
200 {"ok":true} WDA 调用返回成功。客户端可给出成功反馈；端到端验收还要观察手机界面发生预期变化。
400 invalid_control_message body 不是对象或消息结构无效。不得重试成其他 backend。
401 unauthorized session cookie 无效。回到登录流程，不显示“设备离线”。
403 missing_control_header 缺少 CSRF 防护头。修复客户端请求，不放宽服务端。
409 legacy_mirror_uses_webrtc 当前是 mirror。HTTP direct endpoint 不接管旧 data channel。
422 unsupported_control WDA 可操作，但动作不支持。Switcher 属于这一类。
503 released、wda_not_configured 或 wda_unavailable 停止成功提示。released 由用户点“重新连接”；其余检查 WDA runner、relay、锁屏与签名。
网络超时、非 JSON 响应和 ok !== true 都算失败。 不允许“请求已经发出”就画点击圆点、清空文字输入框或弹出成功 toast。当前 web client 的 direct 分支按 ACK 更新反馈；验收时要覆盖失败分支。

四轴状态模型

backend、device、screen 和 control 要分开记录。任意一轴正常都不能替其他轴背书。 当前 /agent/status 已输出前三轴的一部分；control 没有独立字段，必须由 wda_actionable、drivable 和单次 ACK 推导。

轴 当前字段 / 值 如何解释 不能推导什么
backend backend: direct | mirror 进程启动时确定，健康探测抖动不会改变。浏览器取不到 status 时默认 direct，并停止 mirror transport。 direct 不代表 WDA 或画面在线。
device device_state: ready | locked | blocked | offline | released released 优先；之后依次看 wda_actionable、wda_locked、 wda。mode=agent 只说明 WDA runner 可达，不保证它能操作。 wda=true 可能是 locked 或 zombie ready。
screen Direct 当前只返回 screen_state: waiting | offline WDA 可达时是 waiting，否则 offline。真实画面要看 MJPEG 是否持续出帧； MJPEG 失败而 PNG 可用时，验收记录为 degraded。 waiting 不是 live 证明，也不表示帧在更新。
control 当前没有 control_state 字段 候选 ready 条件是 direct、未 released、wda_actionable=true； 最终以每次 POST /control 的 {"ok":true} 和手机可见结果为准。 drivable=true 不能证明某个具体动作已执行。

Direct 状态组合

条件 device screen API control 用户界面
released=true released 不作为画面证据 503 released 显示“手机已交还给你”，由用户重新连接。
wda_actionable=true ready waiting 按动作 ACK 判定 连接 MJPEG；成功出帧后才算 screen live。
wda_locked=true locked waiting 503 或动作失败 要求解锁并保持唤醒，不退回 Mirroring。
wda=true，但不可操作 blocked waiting 503 wda_unavailable 重启 direct device service，检查 Code=41、CoreDevice tunnel。
wda=false offline offline 503 检查 WDA、8100/9100 relay 与签名，不启动 mirror。

安全边界

边界 要求 失败方式
Mac 权限 Direct 不调用 TCC preflight，不加载 AppKit，不构造 ScreenCaptureKit pipeline 或 CGEvent sink。 任何 direct 启动中的 Screen Recording / Accessibility 提示都算回归。
后端选择 只有 PHONE_REMOTE_BACKEND=mirror 可进入 legacy。状态读取失败时，web client 留在 direct。 不得因 WDA、MJPEG、status 或控制失败而自动切换。
WDA 暴露面 Mac 的 8100/9100 iproxy relay 必须只绑定 127.0.0.1，且都指向同一 UDID。WDA 自身没有鉴权； loopback relay 不能阻止同一可路由网络上的主机直连手机端 WDA。 发现 relay 监听 0.0.0.0、控制/画面目标不一致，或手机处于不可信网络时停止验收。 Phase 1 只用于可信隔离网络；必要时关闭手机 Wi‑Fi。
浏览器鉴权 安装器为 LAN 模式生成或复用密码；/control 使用 session cookie 和自定义请求头。 未登录请求必须 401，缺头请求必须 403。
Agent 鉴权 配置 PHONE_REMOTE_AGENT_TOKEN 时，机器调用只接受专用 bearer；否则沿用密码。 不要把 token、密码或 live cookie 写进日志和验收附件。
空闲释放 默认空闲窗口后停止 WDA，把手机交还用户；有 live stream 时不释放。 released 状态下控制必须 503，不能在后台悄悄重启或注入。
WDA 所有权 只有 installer 管理的 loopback supervisor 可设置 PHONE_REMOTE_WDA_MANAGED=true。自定义或远程 WDA 是 external。 external endpoint 不得触发本机 stop、idle release 或 bootstrap；状态要明确由操作者恢复。

从 Mirroring 迁移到 Direct

安装器会保留现有 plist 中的 backend。旧安装已经写入 mirror 时，仅重跑安装命令不会迁移； 必须显式传入 direct。

  1. 记录回滚点 记录当前 release、backend、端口、设备 UDID 和两条 launchd label。密码与 token 只确认“存在”，不要复制进文档。
  2. 准备目标设备 在 Xcode 登录 Apple ID；完成配对、Developer Mode 和开发者信任。第一次设置保持 USB、解锁和亮屏，并明确 WDA_UDID，避免多设备自动选择。
  3. 显式安装 direct 
    PHONE_REMOTE_BACKEND=direct \
curl -fsSL https://raw.githubusercontent.com/leeguooooo/iphone-use/main/install.sh | sh
    安装器会停止旧 daemon、保留密码和受支持的配置，并写入 loopback WDA endpoints。WDA 尚未验证时， direct daemon 仍启动其 HTTP/登录/状态控制面，但明确报告设备层 offline；不会假装 WDA 已就绪。
  4. 建立 WDA 与两条 relay 
    ~/.iphone-use/setup-wda.sh doctor
~/.iphone-use/setup-wda.sh
    setup 必须验证 8100 控制 relay，把 runner 交给独立的 com.leeguoo.iphone-use.wda LaunchAgent，再启动产品 daemon。9100 MJPEG relay 也必须由本次进程持有、绑定 loopback，并指向同一 UDID；失败时不得把任意已有 listener 写成可用画面 URL。运行中断流时，浏览器才降级为静帧并退避重试实时流。
  5. 跑完真机矩阵 至少验证无 TCC、无 Mirroring、实时画面、文字、tap、longpress、swipe、Home、Spotlight、锁屏、 idle release、重连和卸载。Switcher 按“已知不支持”验收。
  6. 关闭旧权限 Direct 证据完整后，再在系统设置撤销 iPhoneUse 的 Screen Recording 与 Accessibility。 撤权后重跑一遍 direct 启动、画面和控制，证明旧权限不是隐性依赖。

回滚到 mirror

回滚是人工选择，不是运行时 fallback。先停 WDA supervisor、runner 和 relay，再显式安装 mirror： 

~/.iphone-use/setup-wda.sh stop
PHONE_REMOTE_BACKEND=mirror \
curl -fsSL https://raw.githubusercontent.com/leeguooooo/iphone-use/main/install.sh | sh

回滚后重新授予并验证 Screen Recording 与 Accessibility。仅看到 daemon loaded 不算回滚完成。

安装、升级与卸载要求

阶段 必须做到 完成证据
全新安装 由已登录的 GUI 用户执行，不用 root。准备 Xcode/Apple ID、配对、Developer Mode、 iproxy。支持路径只用 USB loopback，不自动回退 Wi‑Fi 或 socat。默认写入 direct 与受管 loopback endpoints。 两个 LaunchAgent 状态明确；8100 可用；daemon HTTP 可用；没有 TCC 提示。
升级 配置优先级保持“显式环境变量 > 现有 plist > 默认值”；不能轮换既有密码，不能丢失 backend、UDID、WDA endpoints 或 agent token。每次升级刷新 ~/.iphone-use/setup-wda.sh。 升级前后 status 中 backend/设备一致；新二进制版本正确；WDA supervisor 接管后的替代 runner 可用。
签名续期 免费 Apple ID profile 可能约 7 天到期。WDA 失效时重新运行 setup，不得切换到 mirror 掩盖问题。 WDA app 能启动，8100 status 和 action-level probe 都成功。
停止 setup-wda.sh stop 要停 WDA supervisor、runner、8100/9100 relay；daemon 单独 bootout。 两个 launchd job 不存在，相关进程与监听端口消失。
完整卸载 移除两个 LaunchAgent plist、iPhoneUse.app、产品日志和 ~/.iphone-use。如不再需要，在手机上删除 WDA runner。共享的 Xcode、 Homebrew 和 iproxy 不应自动删除；操作者自行安装的实验性 socat 也不在卸载范围。 重登后 job 不复活；44321/8100/9100 不监听；手机端 runner 按用户选择清除。
安装包现在包含 ownership-gated、幂等的完整卸载器。 它只删除能够证明属于 iphone-use 的 LaunchAgent、PID 记录、应用、日志和状态； 遇到进程身份、路径或仓库状态不明时会保留恢复证据并以非零状态退出。 默认不会动手机上的 WDA runner，也不会删除 Xcode、Homebrew、iproxy 或 socat。

完整卸载

# 先预览；不修改进程、文件、应用或手机。
~/.iphone-use/uninstall.sh --dry-run

# 只卸载当前 Mac 用户下、经 ownership 校验的本机组件。
~/.iphone-use/uninstall.sh

# 如需同时删除手机 runner，必须显式给出目标设备和已安装 bundle id。
~/.iphone-use/uninstall.sh --remove-phone-runner \
  --udid '<exact-iphone-udid>' \
  --bundle-id '<installed-runner-bundle-id>'

卸载器拒绝 root、非规范 HOME、符号链接命名空间、脏的 WDA checkout 和无法核验的活动 PID。 失败时不要手动批量删除保留文件；先按错误输出核对进程与归属，再重试。

真机验收矩阵

每一行都要记录设备型号、iOS、macOS、Xcode、连接方式、构建版本、时间和实际结果。 “通过”需要表内证据，不能用另一行的结果代替。

ID 场景 操作 预期 证据
D01 无 Mirroring 退出 iPhone Mirroring，启动 direct。 daemon、画面、WDA 控制可用；不自动打开 Mirroring。 status JSON、进程列表、浏览器录屏。
D02 无 TCC 在测试机撤销 Screen Recording 与 Accessibility，重启 daemon。 无权限提示；direct 仍能看和控制。 系统设置截图、启动日志、操作录像。
D03 默认选择 全新安装，不传 backend。 backend=direct；安装器不打开 TCC 设置。 live plist、安装日志、status。
D04 旧安装迁移 从 persisted mirror 运行显式 direct 安装和 setup。 旧 daemon 停止；WDA 验证后新 daemon 加载；密码不变。 升级前后 plist 摘要、launchctl、登录验证。
D05 实时画面 在手机上持续滚动 10 秒。 MJPEG 连续更新，无周期性整屏停顿；screen 记为 live。 Safari 录屏、响应 Content-Type、接收字节增长。
D06 画面降级 只中断 9100 relay，保留 8100。 约 2.5 秒 PNG 刷新；页面明确不是实时；控制仍成功。 页面录屏、9100 失败、两次不同 PNG、控制 ACK。
D07 基础控制 执行 tap、longpress、swipe、drag、Home、Back、Spotlight。 每次先收到 {"ok":true}，手机随后出现对应变化。 请求/响应与前后画面对照。
D08 文字输入 在文本框输入 ASCII、中文、emoji，再收起键盘。 字符不丢失、不重复；输入成功后才清空网页文本框。 手机结果截图、浏览器网络记录。
D09 错误 ACK 未登录、删掉控制头、发送无效 JSON。 依次得到 401、403、400；页面不画成功反馈。 HTTP 状态与页面录像。
D10 WDA 不可用 停 WDA supervisor 后发送控制。 503；Mac 光标、焦点、屏幕采集均无变化；backend 仍是 direct。 HTTP、status、Mac 录屏、无 CGEvent 进程证据。
D11 锁屏与 zombie 锁屏；再制造 runner 可达但 action probe 失败的状态。 device 分别显示 locked/blocked；drivable=false；提示要求解锁或重启。 两份 status JSON、恢复时间。
D12 空闲释放 按配置时长停止操作且关闭 live stream。 released=true；控制 503；点“重新连接”后 WDA 恢复。 释放前后 status、launchctl、恢复录像。
D13 状态接口失联 让 /agent/status 临时失败。 web client 保持 direct、停止 mirror transport、显示状态错误。 浏览器网络记录；无 /ws 或 PeerConnection。
D14 Switcher 检查 direct 工具栏并发送 switcher 负向请求。 按钮隐藏或提示改用“搜索”；服务返回 unsupported，不假成功。 页面截图、422 响应。
D15 多设备稳定性 连接两台已配对设备，重启 WDA 和 daemon。 始终使用已固定 UDID；不因重连静默换手机。 配置 UDID、两次 status 与设备画面。
D16 完整卸载 按 lifecycle 清单卸载并重新登录。 两个 job 不复活；44321/8100/9100 不监听；App、plist、日志和状态目录已清理。 launchctl、lsof、文件检查、手机 runner 检查。

现场检查命令

以下命令不打印 token。运行结束后清空 shell 变量和临时 cookie。

1. 后端、设备与 WDA

DAEMON_PLIST="$HOME/Library/LaunchAgents/com.leeguoo.iphone-use.plist"
TOKEN="$(/usr/libexec/PlistBuddy \
  -c 'Print :EnvironmentVariables:PHONE_REMOTE_AGENT_TOKEN' \
  "$DAEMON_PLIST" 2>/dev/null || true)"
[ -n "$TOKEN" ] || TOKEN="$(/usr/libexec/PlistBuddy \
  -c 'Print :EnvironmentVariables:PHONE_REMOTE_PASSWORD' \
  "$DAEMON_PLIST")"

curl -fsS -H "Authorization: Bearer $TOKEN" \
  http://127.0.0.1:44321/agent/status |
  jq '{backend,mode,device_state,screen_state,wda,wda_actionable,wda_locked,
       drivable,released,hint}'

curl -fsS http://127.0.0.1:8100/status >/dev/null
launchctl print "gui/$(id -u)/com.leeguoo.iphone-use"
launchctl print "gui/$(id -u)/com.leeguoo.iphone-use.wda"

2. 浏览器 cookie 与控制 ACK

COOKIE_JAR="$(mktemp)"
PASSWORD="$(/usr/libexec/PlistBuddy \
  -c 'Print :EnvironmentVariables:PHONE_REMOTE_PASSWORD' \
  "$DAEMON_PLIST")"

curl -sS -c "$COOKIE_JAR" \
  -H 'Content-Type: application/x-www-form-urlencoded' \
  --data-urlencode "password=$PASSWORD" \
  http://127.0.0.1:44321/login >/dev/null

curl -fsS -b "$COOKIE_JAR" \
  -H 'Content-Type: application/json' \
  -H 'X-Phone-Control: 1' \
  -d '{"type":"shortcut","name":"home"}' \
  http://127.0.0.1:44321/control |
  jq -e '.ok == true'

3. MJPEG 与 loopback 监听

# 流式请求在 5 秒后超时是预期的；期间应收到 multipart 响应和非零字节。
curl -sS -b "$COOKIE_JAR" --max-time 5 -D /tmp/iphone-use-mjpeg.headers \
  http://127.0.0.1:44321/agent/mjpeg \
  -o /tmp/iphone-use-mjpeg.sample || true
grep -i '^content-type:.*multipart' /tmp/iphone-use-mjpeg.headers
test -s /tmp/iphone-use-mjpeg.sample

lsof -nP -iTCP:8100 -sTCP:LISTEN
lsof -nP -iTCP:9100 -sTCP:LISTEN
# 两条 relay 的 Local Address 必须是 127.0.0.1，不是 0.0.0.0。

4. 收尾

rm -f "$COOKIE_JAR" \
  /tmp/iphone-use-mjpeg.headers \
  /tmp/iphone-use-mjpeg.sample
unset TOKEN PASSWORD COOKIE_JAR

已知限制

限制 当前行为 处理方式
App Switcher WDA 无法合成 home-indicator 系统手势，也没有可点的 WDA element。Direct 不支持。 工具栏隐藏 Switcher，提示用 Spotlight 打开其他 App；不得返回假成功。
WDA 与 Mirroring 互斥 WDA runner 启动会断开 Mirroring，反向也成立。 Direct 验收不依赖 Mirroring；回滚前先停 WDA。
锁屏与休眠 runner 可能仍回答 status，但所有 action 失败。 看 wda_actionable 和 wda_locked，不要只看 wda。
签名有效期 免费 Apple ID 的 WDA profile 可能约 7 天到期。 重跑 setup；发布/长期设备使用稳定签名配置。
MJPEG relay setup 必须证明 9100 listener 属于本次受管进程、只绑定 loopback、并与 8100 指向同一 UDID。 setup 失败时不得继续发布错误 URL；运行期断流时页面降级到 2.5 秒 WDA PNG，并退避重试实时流。
CoreDevice tunnel 睡眠、USB 抖动或 VPN/WARP 可能让 devicectl 卡住或产生 zombie session。 setup 对 devicectl 有超时；由 WDA supervisor 重建，验收记录恢复时间。
screen_state 粒度 Direct 当前只报告 waiting/offline，不能表示 live/degraded。 用实际帧观测补齐证据；若以后扩展 API，要保持向后兼容。
完整卸载 卸载器只清理 ownership 可证实的本机组件；手机 runner 需要显式 UDID 与 bundle id。 先执行 dry-run，再卸载并验证重登后 job 不复活、端口不监听；需要时单独核验手机 runner 已删除。

Phase 2：iOS ScreenCaptureKit companion app 研究闸门

当前状态：未实现，也未承诺可行。 Phase 2 只研究新的设备端画面来源。WDA input 继续保留，除非另一个独立项目证明了可替代的输入方案。

不在文档中猜 entitlement 名称，也不根据 simulator、头文件片段或 WWDC 演示宣布可用。 进入实现评审前，下表每一项都要有 Xcode 和 iOS 27 真机证据。

闸门 要回答的问题 通过证据 失败处理
P2-1 工具链 目标 Xcode 是否包含可编译、可签名的 iOS 27 SDK 接口？ 最小 target 在指定 Xcode 上 clean build，API availability 明确。 停止研究，不用私有 header 或弱链接绕过。
P2-2 Entitlement 第三方开发者能否获得所需 entitlement，并写入目标设备接受的 provisioning profile？ 签名检查显示 entitlement；真机安装和启动成功；不是 simulator 结果。 判定不可交付，不落 companion 生产代码。
P2-3 用户授权 用户需要看到什么授权、录制提示或系统 UI？能否清楚停止采集？ 首启、拒绝、允许、撤销四条路径录像和状态记录。 不能清楚授权或停止时，不进入产品。
P2-4 真机采集 前台、后台、锁屏、受保护内容、旋转与多窗口下分别能捕获什么？ iOS 27 真机帧样本、时间戳、尺寸、像素格式、失败码和系统提示。 把限制写进状态模型；不能用黑帧或旧帧冒充 live。
P2-5 性能 延迟、帧率、功耗、温升和内存是否比 WDA MJPEG 有明确收益？ 同设备、同场景 A/B 数据，包含持续运行与旋转。 收益不成立时继续使用 Phase 1。
P2-6 传输安全 companion 如何与 Mac 配对、鉴权、撤销和升级？是否新增 LAN 暴露面？ 威胁模型、最小权限、密钥生命周期与抓包验证。 不得先开未鉴权端口再补安全。
P2-7 集成 新画面源如何映射 backend/device/screen/control，如何与 WDA input 共存？ 独立 feature flag、状态契约、回滚方案和端到端测试。 失败时回到 Phase 1 direct，不回到 mirror。
Phase 2 的“可行”定义不是能抓到一帧。 entitlement 可交付、用户授权清楚、持续帧稳定、状态可观测、传输有鉴权、升级可回滚，缺一项都不能替换 WDA MJPEG。
