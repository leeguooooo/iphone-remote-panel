接入分两段，WDA 不是可选项

安装器负责 daemon 与 LaunchAgent；随后必须在目标真机上完成 WDA 构建、签名、安装和 USB 中继。耗时取决于 Xcode、签名和设备状态，不承诺固定分钟数。

# 1) 安装已校验的 Release app；skill 和 WDA 脚本固定到 tag commit $ curl -fsSL https://raw.githubusercontent.com/leeguooooo/iphone-use/main/install.sh | sh # 2) 必做：连接、信任并解锁 iPhone，然后完成 WDA 主路径 $ ~/.iphone-use/setup-wda.sh doctor $ ~/.iphone-use/setup-wda.sh $ ~/.iphone-use/setup-wda.sh status # 已校验的 agent skill 和 Claude 发现链接已同时安装

需要完整 Xcode、Apple 开发团队、iPhone 开发者模式、配对/信任、解锁亮屏和 iproxy。普通路径使用 USB，不会自动切换 Wi-Fi 或 socat。

app 会校验对应 Release asset 的 SHA-256；helper 与 skill 使用 tag 的确定 commit。skill 下载、校验、发现链接或安装失败会在替换 daemon 前中止；后续 daemon 失败则恢复旧 skill。管道末端明确使用 IPHONE_USE_SKIP_SKILL=1 sh 才会跳过；这是降级选项，不代表 daemon 与现有 skill 兼容。

升级时，旧 plist 虽没有 backend 字段，但已有有效 loopback WDA URL，会迁移到 Direct；只有完全没有 WDA 配置的旧安装才保留 Mirror。显式 backend 不变。

给 agent 的 API

每次操作都按“看 → 操作 → 验证”执行。所有会改变状态的 POST 除了鉴权，还必须携带 X-Phone-Control: 1 作为 CSRF/操作意图保护；GET 不需要。现有 MCP 服务器提供 12 个工具：状态、截图/元素、snapshot-bound 与严格标签点按、滚动、文字、按键、快捷操作、失败即停的 phone_run_steps 多步执行，以及只重连 canonical managed Direct 目标的 phone_reconnect；MCP client 会自动添加 mutation header。正常安装包把同版本 MCP 放在 ~/Applications/iPhoneUse.app/Contents/MacOS/iphone-use-mcp，不需要另行从源码拼装；同一 binary 的 flow validate/run 还能离线校验并一条命令运行审阅过的 version-1 JSON，--input key=value 只为本次执行注入文字参数，正常路径不调用模型。浏览器控制栏也提供「流程」录制：只保留确认成功的动作，优先语义标签，把文字原文丢弃并转换成运行参数，再在人工安全审核后保存脚本或运行全部步骤；之后可用「打开脚本」恢复步骤、重新填写参数并直接重放，不再调用模型。

# 先检查固定目标是否真的可操作 $ curl -H "$AUTH" $HOST/agent/status {"backend":"direct","target_configured":true, "managed_wda":true,"recovery_owner":"daemon", "wda_actionable":true,"drivable":true}
# 再操作，并检查 HTTP 状态 $ MUTATION="X-Phone-Control: 1" $ curl -H "$AUTH" -H "$MUTATION" -X POST "$HOST/agent/input" \ -d '{"type":"tap","label":"新备忘录"}' $ curl -H "$AUTH" -H "$MUTATION" -X POST "$HOST/agent/input" \ -d '{"type":"text","text":"你好世界"}'

它现在承诺什么

WDA 是默认依赖

Direct 需要完整的 WDA setup。只有 daemon 启动，不等于画面和控制已经可用。

HTTP 确认式控制

/control 和 /agent/input 不把“已接收”冒充“已执行”。遇到 504 outcome_unknown，先看画面/状态，不能盲目重发。

元素与 Unicode

/agent/elements 返回手机辅助功能树；文字由 WDA 送入输入框，不经过 Mac 键码。

Direct 不申请 TCC

安装器保留已有有效签名；无有效签名时才 ad-hoc 签名。稳定 TCC 身份只服务于 legacy mirror。

Mirror 是兼容后端

只有显式设置 PHONE_REMOTE_BACKEND=mirror 才启用 ScreenCaptureKit、WebRTC、TURN、CGEvent 与对应 TCC 权限。

真机证据分层

已有 WDA 组件记录；安装器、MJPEG、浏览器手势、恢复和多设备整链路仍须按验收文档实测。

Phase 1 的网络边界

daemon 的密码、cookie 和 bearer 只保护 44321。iPhone 上 WDA 的 8100/9100 没有认证；USB iproxy 固定 Mac relay 的目标，但不能阻止同一可路由网络 直接访问手机端 WDA。当前版本只应运行在可信、隔离网络。真正的设备传输认证要由 Phase 2 companion app 或受控 tunnel 提供。
