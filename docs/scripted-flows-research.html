iphone-use · competitive research · 2026-07-28

录一次，不等于回放点击；要保存的是意图、定位方式和结果

目标不是让 AI 每次重新看图操作，也不是把一次探索冻结成坐标脚本。 正确分层是：AI 负责第一次探索和失败修复，确定性 runner 负责绝大多数重复执行。

产品决策：继续做，但不做通用 Mobile MCP 的复制品。

iphone-use 的差异化应是真实个人 iPhone、浏览器人工接管、低 Token flow 重放。MCP 是 Explore/Repair 的入口；Flow runner 才是 Run 的主体。正常重放不调用模型，不把截图塞给模型，也不保存临时 snapshot ref。

证据范围：公开竞品文档 + 当前仓库源码 尚未证明：真实 iPhone 上的小红书完整重放 不在本阶段：实现 workflow engine

竞品不是一个答案，而是四个不同层

产品 做得好的层 值得吸收 不能直接替代我们
Mobile MCP AI 探索与设备能力入口 可访问性树优先，截图坐标兜底；支持真实 iOS 设备 它自己明确建议：探索完成后转到 Mobilewright 做确定性测试
Mobilewright 确定性 locator runner lazy locator、每步重新解析、自动等待、稳定 bounds、严格断言、失败留证 建立在 mobilecli 生态；直接接入会绕开现有 daemon、浏览器和 WDA 生命周期
Maestro Flows 易写、易读、可组合的 flow DSL 子 flow、变量、条件、有限循环、自动等待、关系 selector、Studio 点选插入 本地 iOS 只支持 Simulator；官方文档仍明确不支持物理 iOS 设备执行
Appium Inspector / MCP 检查、录制、代码生成和证据 录制交互生成可执行代码；headless/NO_UI 模式去掉重复 UI 负担；动作证据可选 完整 Appium 栈复杂，且“录制出来的代码”仍需要 locator 质量审查
行业共识 元素树是默认观察面，截图是像素信息、失败证据或无可访问性控件时的兜底。 录制器应生成可编辑的确定性步骤，而不是继续让 LLM 执行整段自然语言。

当前项目离“可靠脚本化”还差什么

当前事实影响需要的修正
ElementRow 已补充 identifier、enabled、visible、accessible、focused、placeholder 只读观察面已有 durable locator 的原料，但当前动作接口仍不能组合这些条件 下一步设计严格 locator 查询；继续保留 snapshot 作为临时元素的安全边界
phone_tap_label 已改为精确唯一匹配，并通过 snapshot-bound index 执行动作 重名标签现在会零动作失败，但仍无法表达父容器、角色、状态或相对锚点 增加完整 strict locator 查询；支持 identifier、role、state 和 ancestor 组合
skill 建议把 curl + sleep + 坐标冻结成脚本 动画、A/B 页面、设备尺寸和列表重排都会造成误点 保存前置条件、locator、动作、后置断言和 timeout
已有 snapshot token 只保护当前元素列表 它适合交互面板，不适合长期保存 明确区分 ephemeral ref 与 durable locator
失败只有 HTTP 层结果，没有统一 flow artifact AI 修复时缺少最后一步、树 diff、截图和应用状态 定义 repair bundle，失败时一次性收集

建议产品模型：Explore → Teach → Run → Repair

01 / EXPLORE AI + 人探索 读取元素树；必要时看截图；记录每一步的意图、候选 locator 和结果。
02 / TEACH 编译为草稿 参数化输入，删掉推理，补齐前后置断言、风险级别和失败策略。
03 / RUN 零模型执行 每一步重新解析 locator、自动等待、严格唯一匹配；成功路径不调用 AI。
04 / REPAIR 显式修复 失败即停；生成最小证据包；AI 只修坏掉的 locator 或分支，产生新版本。

关键边界

可以长期保存bundle/app 身份、参数、语义 locator、timeout、断言、风险策略、有限分支和有限循环
只能当前快照使用元素 index、snapshot token、WDA element id、临时坐标框
默认不保存密码、验证码、Cookie、会话 token、用户私密内容、截图中的敏感像素
只能作兜底绝对坐标、归一化坐标、纯视觉点击；必须有紧邻的状态断言

Flow 应保存“合同”，不是点击流水账

下例只是研究阶段的可读草案，不是现在就承诺的最终文件格式。重点是字段语义： runner 必须知道开始状态、怎样找到目标、什么算成功，以及不确定时能不能重试。 

version: 1
id: rednote.search_and_open
target:
  platform: ios
  app: ${APP_BUNDLE_ID}
inputs:
  query: { type: string, required: true }

preconditions:
  - app_foreground: ${APP_BUNDLE_ID}
  - any_visible:
      - { id: search_entry }
      - { role: button, label: "搜索" }

steps:
  - id: open_search
    action: tap
    locator:
      strict: true
      prefer:
        - { id: search_entry }
        - { role: button, label: "搜索" }
        - { role: button, near: { label: "首页" } }
    wait:
      until: { role: textfield, focused: true }
      timeout_ms: 5000
    retry:
      only_if_not_sent: 1
    evidence: on_failure

  - id: enter_query
    action: fill
    locator: { role: textfield, focused: true }
    value: ${query}
    postcondition: { value: ${query} }
    idempotency: replace

  - id: submit
    action: key
    name: return
    postcondition:
      any_visible:
        - { text: ${query} }
        - { id: search_results }
    on_unknown: stop_and_inspect

on_failure:
  collect: [status, foreground_app, element_tree, screenshot, last_action]
  policy: stop_and_repair

Locator 优先级

  1. accessibility identifier / test id：最稳定，也不受语言影响。
  2. role + label + state：符合用户可见语义，必须严格唯一。
  3. 父子或相对锚点：解决“每张卡片都有一个更多按钮”。
  4. 文本正则 + 有界 index：只能在稳定容器内使用。
  5. 坐标：最后兜底；绑定屏幕特征与前后断言，不自动跨设备复用。
禁止“看到没变化就再点一次”的通用自愈 页面没变化可能是网络慢，也可能是第一次点击已经产生外部副作用但响应未回来。 只有服务端明确返回 outcome:not_sent，且动作仍然符合当前前置条件时， runner 才能自动重试。outcome_unknown 必须先重新观察。

小红书不是普通表单：脚本必须面对动态内容

场景偷懒做法可靠做法
信息流卡片复用、顺序变化 点击第 3 张卡片 用卡片内标题/作者作锚点，再在该容器内找动作
无限滚动 固定 sleep 后连续滑动 有限循环：每轮验证目标或列表进度，并设置最大次数
A/B 文案、国际化 只保存一个中文按钮名 identifier 优先；否则显式候选集，不做模糊全局点击
登录、青少年模式、权限弹窗 把弹窗当异常坐标点掉 作为命名分支；未知弹窗停下，不猜“允许/确认”
点赞、评论、发布、关注 失败就自动重试 标记外部副作用；执行前确认身份/内容，未知结果先读状态
平台策略和账号风控 追求无人值守高频执行 频率上限、人工接管、审计记录；不设计绕过风控的能力

落地顺序：先补观察协议，再做录制器

阶段产物为什么先做
P0 已完成：元素协议补充 identifier、enabled、visible、accessible、focused、placeholder 没有可表达的稳定 locator，录制器只会制造脆弱脚本
P0.5 已完成：MCP 暴露 snapshot-bound element tap；精确 label 必须唯一匹配，重名时零动作 先消除“默认点击第一个匹配”的误操作风险，再扩展 locator 语法
P1 部分完成：wait_for 与 tap_locator 共用 application + label/id/kind/value/focus/enabled/visible 的 strict match；ancestor/容器关系待补 先证明定位质量，不急着执行动作
P2 已完成第一版：POST /agent/actions + MCP phone_run_steps；整批预校验、单 WDA 锁、最多 24 step、wait/assert、失败即停 覆盖最常见重复任务，同时保持安全面可审计
P2.5 已完成第一版：iphone-use-mcp flow validate/run <file>；严格 version-1 JSON、离线校验、Direct + drivable preflight、单批提交、零自动重试 把已理解的稳定段落变成真正的一条命令；正常路径不再调用模型
P3 已完成第三版：浏览器「流程」面板记录成功动作 → 优先保存唯一语义标签 → 文字原文丢弃并转换为运行参数 → 对比动作前后元素树并自动建议 wait_for → 标记易失坐标 → 人工成组重排/删除/安全确认 → 保存脚本或运行全部步骤；无法稳定录入的动作形成“不完整草稿” 录制必须建立在稳定 locator 和 runner 已验证的前提上
P4 Repair bundle + AI patch；版本化历史与回滚 失败修复是稀有路径，不应先于确定性执行内核
P5 MCP：list/run/inspect/repair_flow，而不是暴露几十个原子工具 MCP 应编排产品能力，而不是成为 workflow engine 本身

真正完成的验收标准

  • 同一小红书 flow 连续运行 20 次，正常路径不调用模型。
  • 不同内容顺序下仍通过语义 locator 找到同一目标，不依赖固定列表 index。
  • 人工插入一个未知弹窗时，runner 停止并生成 repair bundle，不误点确认。
  • 模拟请求超时且结果未知时，不自动重复评论、点赞、发布或发送。
  • 失败报告包含最后成功步骤、当前元素树、前后 diff、截图和设备/应用状态。
  • 坐标 fallback 在另一机型或界面特征不匹配时拒绝执行。
  • 人工可在浏览器中接管，并能从明确 checkpoint 继续，而不是重跑整条 flow。
当前证据结论 仓库已经有真实 iPhone WDA、元素树、snapshot 防旧引用能力，以及严格唯一的 label tap / snapshot-bound element tap；现在也有了有界多步 runner， 支持 durable tap_locator、整批预校验、semantic wait/assert、 首错停止、已完成 step 证据与整批重放安全标记。release-matched MCP binary 还可离线校验并直接运行 user-owned version-1 flow 文件，正常路径不需要模型。 浏览器 Teach UI 已可录制已确认成功的 Home/搜索、语义标签点按和坐标 手势；文字原文不会持久化，而是转换为每次执行时填写的显式 string 参数。 CLI 同样支持 flow run --input key=value，并在接触 daemon 前拒绝 缺失、未知、重复或未定义参数。在元素树出现可证明的新唯一 accessibility identifier 或前台应用时自动追加可审核的 semantic wait；自动检查点不会复制可能包含 姓名、余额的任意画面标签和值。找不到可靠检查点时会明确保留短等待，不会伪造 locator。逐项审核后可保存合法 v1 JSON 或一次批量执行；后续浏览器会话可以 通过「打开脚本」在严格校验后恢复步骤、重新填写运行参数并直接重放。 但仍没有 ancestor/container locator、托管 flow store、repair bundle 或上述 20 次真机重放证据。因此“多步执行内核已具备”成立，“完整脚本化产品已完成” 仍不成立。
